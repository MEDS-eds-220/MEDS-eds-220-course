Conda environments code along key

Instructor key for the Conda environments code along. This page is not linked from the site navigation. Section numbers match the “Hands-on environments” sections in the lesson. Each check-in from the lesson appears in a green box, followed by its answer.

Slides: What are environments and what is Conda?

Setup

  1. Open a terminal.

1. List environments

conda env list

conda info --envs gives the same output.

  • This command shows all the Conda environments available on your computer and their location.
  • The asterisk next to the environment path indicates which environment is active.
  • The active environment also appears in parentheses at the start of the terminal prompt, for example (base).

2. Create new Python environment

conda create --name test-env python=3.11

This creates a new environment called test-env and, within it, installs Python 3.11. Without a version (conda create --name test-env python), Conda installs the most recent version of Python.

When you run it, it gives you information about the packages that will be installed and asks whether to proceed. Type y and press enter to create the environment and install the packages.

Check-in

Check whether the new test-env environment is listed by Conda. Is it activated or not?

Answer:

conda env list

test-env is listed but not activated: the asterisk is still next to base.

3. Activate environment

conda activate test-env
Check-in

Verify that test-env is now your current environment.

Answer:

conda env list

The asterisk is now next to test-env, and the prompt starts with (test-env).

Check the Python version:

python -V

4. Packages information

See which packages are installed within the environment:

conda list

Point out the name, version, build and channel columns. The channel column is blank for packages from the default channel.

Check if pip is installed:

conda list pip

Check if numpy is installed (it is not, so the columns are empty or you get CondaValueError: No packages match 'numpy'):

conda list numpy

5. Searching for and installing packages

Install numpy from the default channel:

conda install numpy
Check-in

Verify that numpy is now installed.

Answer:

conda list numpy

Optional: enter the Python interpreter and use numpy.

python
import numpy as np
x = np.array([1,2,3])
x*2

Press Ctrl + D to exit the Python interpreter.

Search for packages

Warning

Depending on whether this is being run with a standard Anaconda installation or not, it might actually find it in the conda-forge channel by default. If so, roll with it and move to the check-in.

Search for contextily in the default channels (it is not there):

conda search contextily

Search for it in the conda-forge channel:

conda search --channel conda-forge contextily
Check-in

In your output, do you see any versions of contextily with multiple builds?

Answer: Yes. Look for a version number that is listed more than once, each time with a different build string.

Install contextily from conda-forge. Point out the “Solving environment” step while it runs.

conda install --channel conda-forge contextily
Check-in
  1. Check whether rasterio is installed in the environment.
  2. Which channels were used to install dependencies for contextily?

Answer:

conda list rasterio
conda list
  1. Yes. rasterio was installed as a dependency of contextily.
  2. The channel column shows conda-forge for the new dependencies. Packages that were already in the environment from the default channel still have a blank channel column.

6. Deactivate environment

conda deactivate

Returns to the base environment.

Check-in

Verify we are no longer in the test-env. What environment are we on?

Answer:

conda env list

The asterisk is next to base, and the prompt starts with (base).

7. Delete environment

conda remove --name test-env --all

Type y and press enter to delete the environment.

Check:

conda env list

8. Create environment (one liner)

Create a new environment called my-env with the contextily and numpy versions we had before, prioritizing conda-forge:

conda create --name my-env contextily=1.7.1 numpy=2.4.6 --channel conda-forge
Check-in

Activate the environment and take a look at the dependencies that were installed with these two packages.

Answer:

conda activate my-env
conda list

Leave my-env active for the next section.

9. Exporting an environment

Check which directory you are in before exporting (pwd on Mac and Linux, echo %cd% in Windows CMD). The .yml files are created there.

Platform and package specific

conda env export > environment.yml

Check:

ls
less environment.yml

Press q to exit.

Point out the channels, the build strings and the prefix line, which should be deleted before sharing the file. Because every package has a build string, this file may not work on other operating systems.

Cross-platform compatible

conda env export --from-history > environment_hist.yml

Check:

less environment_hist.yml

Mention they would have to remove the file path at the end.

Press q to exit.

Only numpy=2.4.6 and contextily=1.7.1 appear. The channels come from your Conda settings (defaults), so you would need to add conda-forge by hand to recreate the environment.

Clean up

Delete both files and the example environment:

rm environment.yml environment_hist.yml
conda deactivate
conda remove --name my-env --all

Check:

ls
conda env list

Exercise

  1. Create a Conda environment called plot-env with the most recent versions of Python and matplotlib (no need to specify a channel).
  2. Activate the environment and check which version of matplotlib is installed.
  3. Export the full environment specs as environment_ex.yml and take a look at it.
  4. Return to the base environment and remove the plot-env environment.
  5. Verify the environment was removed.
  6. Remove the environment_ex.yml file.
  7. Verify the file was removed.
Solution 
# 1
conda create --name plot-env python matplotlib

# 2
conda activate plot-env
conda list matplotlib

# 3
conda env export > environment_ex.yml
less environment_ex.yml   # press q to exit

# 4
conda deactivate
conda remove --name plot-env --all

# 5
conda env list

# 6
rm environment_ex.yml

# 7
ls

10. Importing an environment

Setup:

  1. Download the eds220-env.yml file from the course repository and move it to a directory for a mock project.
  2. In the terminal, go to that directory.
conda env create --name eds220-env --file eds220-env.yml
Check-in

Verify that the new environment was created, activate it, and take a look at the installed packages.

Answer:

conda env list
conda activate eds220-env
conda list
